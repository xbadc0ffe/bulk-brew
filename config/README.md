# Config

Versioned data files that hold every judgment call the builder makes. Logic lives in `packages/core`; numbers and rules live here, so tuning never needs a code change. Both apps load these files, and the iOS app can refresh them over the air together with the card data. The reasoning behind the numbers is in `docs/guides/`.

| File                     | Purpose                                                                                                              | Status  |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------- | ------- |
| `settings.defaults.json` | Default user settings: copy limits per deck size, unlimited basics, Un-sets, art toggle.                             | present |
| `deck-templates.json`    | Per deck size: base lands and land formula, default curve profile, type mix, role quotas, tolerances.                | present |
| `curve-profiles.json`    | Spell distributions by mana value: aggro, midrange, control, jumpstart.                                              | present |
| `roles.json`             | Role definitions (removal, card advantage, finisher, ...) as matchers over tags, keywords, types, and derived facts. | present |
| `archetypes.json`        | Synergy archetypes (enablers, payoffs, minimums) and composition archetypes (aggro, midrange, control).              | present |
| `synergy-rules.json`     | Enabler and payoff matcher pairs with weights.                                                                       | present |
| `land-rules.json`        | Basic land names, nonbasic scoring (one color and multi-color), how conditional tapped lands enter, land caps.       | present |
| `builder-weights.json`   | Objective weights, tiebreak order, local search limits, deck score weights, best fit candidate counts.               | present |
| `card-strength.json`     | Card strength score weights: popularity, stats, keywords, effects, removal quality, cost, pips.                      | present |
| `theme-rules.json`       | Setup and payoff jobs per themed style, the false friends, and the minimums a decent bulk deck needs at each size.   | present |
| `theme-bulk.json`        | Computed: each themed style's mean setup and payoff per bulk card of each color class. Never edited by hand.         | present |
| `card-needs.json`        | What each ability of a card depends on, read from its rules text: vocabulary, templates, credit clauses, supply.     | present |
| `tag-overlay.json`       | Local tag fixes and gap-fills applied on top of Scryfall Tagger tags at pipeline time.                               | present |
| `display-tags.json`      | Short tags shown on cards and offered as filters ("Removal", "Draw", "+1/+1"), from roles, styles, and tags.         | present |
| `learned/plans.json`     | Learned from real decks: each style's profile per size (theme cards, roles, curve, types) and theme shares in bulk.  | present |
| `learned/tags.json`      | Learned from real decks: tags each style's decks play more than real decks in general, and tag pairs.                | present |

Every file carries a `version` field. A deck records the joined config version it was built with (see `configVersion()` in `packages/core/src/config.ts`). `display-tags.json` is display only: the builder never reads it, so it is not part of that version.

`theme-rules.json` holds the theme guide (`docs/review/themes.md`) as rules: each rule reads a card's tags, types, keywords, mana value, and power, and regular expressions over its oracle text (reminder text removed) and type line. A card counts once per style, as setup or as payoff. Besides the rules and `minimums`, a style can give `kin` (other styles that use the same resource, nearest first: where a request the pool cannot support falls back), `setupNeedsPayoff` (its setup does nothing without its own payoffs, so other themes do not take it as setup), and `lacks` (for every floor its minimums use, a short phrase a player reads when the pool misses it). The format and how the rules were set: `docs/review/theme-rules.md`. Any edit bumps the rules `version` and must be followed by `npm run theme:bulk`: `theme-bulk.json` records the rules version it was computed with, and validation fails while the two differ.

`theme-bulk.json` is written by `npm run theme:bulk` from the data pack and the rules, never by hand: every common and uncommon (Un-sets left out, nonlands plus modal double-faced land cards), read at 60 cards. It records the data pack it was read from; rerun it after a new pack. Its version is a hash of the content and joins the config version.

`learned/` is written by `npm run learn:build`, never by hand; its versions are hashes of the content and join the config version. The judgment about how the builder uses it (weights per size, combo results and brackets) stays in `builder-weights.json` under `learned` and `combos`.

Edit, then run `npm run config:check`: it validates shapes and cross-references, confirms every tag slug exists in the current data pack, and prints per-color match counts for each role, archetype, and display tag. The same validation runs in `npm test`.

Builder tiebreaks in `builder-weights.json` apply in list order after one fixed leading check: a card that fills a curve bucket still below its target beats one that does not. Card id breaks any remaining tie.

The `grow` block in `builder-weights.json` holds the constants of the grow builder (`packages/core/src/grow.ts`), which builds a style the player asks for by name at 60, 40, and 100 cards from the theme rules. The reasoning behind each is in `docs/review/proto-b.md`, "Constants".

| Key                 | Meaning                                                                                                                                               |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `marginFull`        | Best fit (not used by `buildDeck` yet): a theme whose pool holds this many times its floors counts in full.                                           |
| `richnessCap`       | Best fit: richness over plain bulk (`theme-bulk.json`) counts up to this.                                                                             |
| `richSeed`          | Seed this much over the payoff floor when both halves of the pool hold twice their floors.                                                            |
| `commanderCredit`   | Copies a commander's theme job counts as. The rules count a commander as one card, so 1.                                                              |
| `commanderPlan`     | Best fit: a theme the commander pays off scores this much higher.                                                                                     |
| `offPlanGateWeight` | A payoff of another style at this weight or more enters only when that style's setup in the deck covers it.                                           |
| `fullSlot`          | A theme card whose mana value slot is already at its curve target counts this much in the seed and grow steps.                                        |
| `setupPull`         | Extra value the plan's setup keeps in the role and curve fills while the deck sits at its setup floor.                                                |
| `setupTarget`       | The setup pull fades to nothing at this multiple of the setup floor (above 1).                                                                        |
| `nearMargin`        | A style whose pool reaches this share of its floors is short: offered, and answered with a note and the nearest deck. Below it the style is left out. |

`land-rules.json` scores nonbasic lands for the mana base (`packages/core/src/lands.ts`; the reasoning is in `docs/guides/mana-base.md`). Multi-color decks use `nonbasic` with the `colors` block. A one-color deck scores a nonbasic against the basic it replaces, so the basic scores 0 and a land gets in only above `mono.minScore`: making the deck color, or any color, gains nothing; the costs are `nonbasic.entersTapped` (scaled by the chance the land enters tapped), and the `mono` costs below; `nonbasic.utility` counts only on a land that costs nothing against a basic and whose color identity fits the deck. Lands whose mana depends on a draft (Paliano, the High City) never enter a mana base.

| Key                       | Meaning                                                                                                                                                                                                                                                                                                                  |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `mono.lifeToEnter`        | Per life a land lets you pay to enter untapped (shock lands); it costs this or the tapped cost, whichever is less.                                                                                                                                                                                                       |
| `mono.lifePerTap`         | Per life paid each time the land taps for the deck color ("{T}, Pay 1 life", painland damage).                                                                                                                                                                                                                           |
| `mono.drawback`           | A land with one of `mono.drawbackTags`, such as "sacrifice it unless you tap an untapped permanent" or "sacrifice a Plains instead".                                                                                                                                                                                     |
| `mono.drawbackTags`       | Tags that mark a land's drawback.                                                                                                                                                                                                                                                                                        |
| `mono.noDeckColor`        | A land that makes no mana of the deck color, as `landColors` reads it.                                                                                                                                                                                                                                                   |
| `mono.planUtility`        | Gain for a land with one of `mono.planTags` for one of the deck's styles, whatever its costs, when its color identity fits the deck and it has an ability beyond its mana and what it does as it enters (a one-time "When this land enters, surveil 1" is a rider, not a plan). At 2 it outweighs entering tapped alone. |
| `mono.planTags`           | Tags by style id whose ability helps that plan: `mill-self` (Dakmor Salvage's dredge) helps a Graveyard deck.                                                                                                                                                                                                            |
| `mono.minScore`           | One-color nonbasics scoring below this stay out. Above 0, so a land must beat the basic.                                                                                                                                                                                                                                 |
| `entering.readsUntapped`  | A land at or below this chance to enter tapped reads as untapped: it is not called tapped in its note and keeps its utility in one-color decks.                                                                                                                                                                          |
| `entering.landsPlayed`    | Land drops in a typical game per size, for "unless you control two or more other lands" (tapped on the first two of them) and its kin.                                                                                                                                                                                   |
| `entering.basicInPlay`    | Chance to enter tapped for "unless you control a basic land" or a basic land type the deck runs.                                                                                                                                                                                                                         |
| `entering.revealFromHand` | Chance to enter tapped for "you may reveal a Swamp card from your hand" when the deck runs that type (or the tribe it names).                                                                                                                                                                                            |
| `entering.lowLife`        | Chance to enter tapped for "unless a player has 13 or less life".                                                                                                                                                                                                                                                        |
| `entering.legendInPlay`   | Chance to enter tapped for "unless you control a legendary creature" in Commander; outside it, such a land reads as tapped.                                                                                                                                                                                              |

The data pack marks a land `entersTapped` whenever its text says it enters tapped, conditions and all. `landEntry` reads the condition against the deck: a basic land type against the basics of its colors, "two or more opponents" as untapped in Commander only, "pay 2 life" as a life cost instead. A condition it does not know reads as always tapped. The same chance counts toward the multi-color tapped cap (`colors.tappedMaxShare`) and scales `colors.entersTappedMulticolor`.

`card-needs.json` drives the card needs reader (`packages/core/src/card-needs.ts`, step 2 of `docs/builder-phase2.md`). The reader splits a card's text into abilities (faces, Saga chapters, Class levels, modal bullets, keyword lines; reminder text removed; the card's names and "this creature" read as `~`) and each ability into its cost, trigger, conditions, and sentences. For every resource an ability refers to, it records where the resource appears (condition, trigger, cost, selection, count, replacement, additional cost) and its kind: a need (the ability does nothing without it), a bonus ("instead", "costs less", "or pay", "as long as ... gets +N/+N" on a body, "also", a count above a base), a drawback (an "unless" or "if you don't" over an effect that harms its owner), or nothing (unconditional; the body and keyword abilities always are). Resource ids follow `family:value`: `tribe:Elf`, `type:artifact`, `subtype:Food`, `land:Forest`, `counters:+1/+1`, `graveyard:creature`, `cast:noncreature`, `color:R`, `devotion:B`, `keyword:flying`, and the plain `lifegain`, `lifeloss`, `tokens`, `death`, `sacrifice`, `discard`, `spells`, `creatures`, `power`, `commander`, `energy`, `experience`, `format:multiplayer`. The parsing logic stays in code; the words and templates live here. Its `version` joins the config version as `n`.

| Key             | Meaning                                                                                                                                                                                                                                                                                                                                                                                   |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `vocabulary`    | Subtype lists from the Comprehensive Rules 205.3 (creature, artifact, enchantment, land, spell, planeswalker, battle types), plurals that are not the word plus s or es, groups such as `outlaw`, the nouns a card uses for itself ("this creature"), number words, subtypes with their own sacrifice ability, and creature keywords a card can be selected by ("creatures with flying"). |
| `keywords`      | Keyword abilities with a dependency (`Affinity for`, `Delve`, `Champion`, `Splice onto`, ...): kind, place, and the resources, or an object read from the words after the keyword. Every other keyword is unconditional.                                                                                                                                                                  |
| `harmful`       | Effects that harm the card's owner (sacrifice, life loss, discard, "can't", entering tapped): an "unless" or "if you don't" over one is a drawback.                                                                                                                                                                                                                                       |
| `statOnly`      | A clause that only changes power and toughness: under "as long as" on a card with a body it is a bonus.                                                                                                                                                                                                                                                                                   |
| `bonusSentence` | Sentences whose refs are bonuses: the card's own cost reductions and alternative costs.                                                                                                                                                                                                                                                                                                   |
| `resourceWords` | Words that name a resource. A condition, trigger event, or cost part that no template reads and that has none of these words and no type is read as game state ("if you win the flip"): it asks nothing of the deck. The coverage report counts these.                                                                                                                                    |
| `templates`     | Regular expressions (case-insensitive) in four lists: `trigger` (matched at the start of a trigger, up to its comma), `condition` (a whole condition after "if", "unless", "as long as", "only if"), `cost` (a whole cost part), and `effect` (anywhere in a sentence, in list order; each match is read once). Fields below.                                                             |
| `mentions`      | Words that name a resource (graveyard, counters, tokens, card types, ...). One that no template read, or a type word, leaves its ability unparsed with that reason.                                                                                                                                                                                                                       |
| `credits`       | The clause that earns each credit: `roles` (one per role in `roles.json`: `body` for credits the body earns, `bodyKeywords`, or a `clause` expression), `strength` (one per effect label in `card-strength.json`; `role` reuses a role's pattern, `always` marks a penalty not tied to a clause), and `themeTags` (clause patterns for theme rules that read tags only, by tag).          |
| `supply`        | Where a deck's supply of a resource comes from, by resource id: `theme` counts the cards that are that theme's setup in `theme-rules.json` (one meaning for "a lifegain source"), `text` also counts what the reader finds in text, `freeCount` is the count any deck meets ("a card in your graveyard"). Other resources count from types, type lines, and text.                         |
| `thresholds`    | Copies a deck needs to supply a resource, per deck size: `base`, `families` by family or resource id, `perCount` added per counted item beyond the first ("three or more artifacts"), and `unparsedScale`, the factor an unparsed ability's named resources need.                                                                                                                         |

Template fields: `re`; `res` (fixed resources, any one meets the ref); `obj` (how the `{obj}` capture is read: `yours`, `graveyard`, `cast`, `card` for a card in a library or hand, `token` for what a token is); `ubiquitous` (what an object every deck has stands for, as `death` for "a creature you control dies"); `supplies` or `supply` (the phrase makes the resource rather than needing it, which is how a card supplies its own need); `counter` (read a counter kind); `place` and `kind` (overrides); `negated` ("you control no Islands"); `event` (a condition that is the event itself, so "instead" does not make it a bonus); `optional` (an action a following "If you do" depends on); `typed` (match only when the object names a resource); `ignore` (read, names nothing). Placeholders: `{obj}`, `{tok}`, `{n}` (a captured count), `{num}`, `{counter}`, `{color}`, `{mana}`; `~` is the card itself.

A deck meets a need when the card supplies it itself, or when the deck's other cards supply one of its resources to the threshold: creatures of a type for a tribe (changelings count), the deck's creatures for `graveyard:creature` (cards reach the graveyard by being played), the deck's colors for `color:` and basic land types. A clause in an unparsed ability needs what its words name, at `unparsedScale` times the threshold. `npm run needs:report` reads the whole pack and writes the coverage summary to `docs/review/needs-coverage.md` and the unparsed work list, by shape and rarity, to `data/review/needs/unparsed.md`.
