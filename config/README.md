# Config

Versioned data files that hold every judgment call the builder makes. Logic lives in `packages/core`; numbers and rules live here, so tuning never needs a code change. Both apps load these files, and the iOS app can refresh them over the air together with the card data. The reasoning behind the numbers is in `docs/guides/`.

| File                     | Purpose                                                                                                                                                                                                                                                                               |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `settings.defaults.json` | Default user settings: copy limits per deck size, unlimited basics, Un-sets, art toggle, the rarities the builder may use.                                                                                                                                                            |
| `deck-templates.json`    | Per deck size: base lands and land formula, default curve profile, type mix, role quotas, tolerances, the half cast rule (20).                                                                                                                                                        |
| `curve-profiles.json`    | Spell distributions by mana value: aggro, midrange, control, jumpstart.                                                                                                                                                                                                               |
| `roles.json`             | Role definitions (removal, card advantage, finisher, ...) as matchers over tags, keywords, types, and derived facts.                                                                                                                                                                  |
| `archetypes.json`        | Style ids, labels, and descriptions; enabler and payoff matchers and minimums for the classic builder: secondary styles only.                                                                                                                                                         |
| `synergy-rules.json`     | Enabler and payoff matcher pairs with weights.                                                                                                                                                                                                                                        |
| `land-rules.json`        | Basic land names, nonbasic scoring (one color and multi-color), how conditional tapped lands enter, land caps.                                                                                                                                                                        |
| `builder-weights.json`   | The grow builder's and the plan picker's constants (`grow`, `picker`), Build page options, commander and secondary style rules, learned data and combo weights, and the classic builder's objective, tiebreaks, local search, deck score, best fit counts, and castability penalties. |
| `card-strength.json`     | Card strength score weights: popularity, stats, keywords, effects, removal quality, cost, pips.                                                                                                                                                                                       |
| `theme-rules.json`       | Setup and payoff jobs per themed style and per creature type (tribes), the false friends, and the minimums a decent deck needs.                                                                                                                                                       |
| `theme-bulk.json`        | Computed: each themed style's mean setup and payoff per bulk card of each color class. Never edited by hand.                                                                                                                                                                          |
| `card-needs.json`        | What each ability of a card depends on, read from its rules text: vocabulary, templates, credit clauses, supply.                                                                                                                                                                      |
| `tag-overlay.json`       | Local tag fixes and gap-fills applied on top of Scryfall Tagger tags at pipeline time.                                                                                                                                                                                                |
| `display-tags.json`      | Short tags shown on cards and offered as filters ("Removal", "Draw", "+1/+1"), from roles, theme rule jobs, and tags.                                                                                                                                                                 |
| `learned/plans.json`     | Learned from real decks: each style's profile per size (theme cards, roles, curve, types) and theme shares in bulk.                                                                                                                                                                   |
| `learned/tags.json`      | Learned from real decks: tags each style's decks play more than real decks in general, and tag pairs.                                                                                                                                                                                 |

Every file but `settings.defaults.json` carries a `version` field. A deck records the joined config version it was built with (see `configVersion()` in `packages/core/src/config.ts`). `display-tags.json` is display only: the builder never reads it, so it is not part of that version.

`theme-rules.json` holds the themes as rules: each rule reads a card's tags, types, keywords, mana value, and power, and regular expressions over its oracle text (reminder text removed) and type line. A card counts once per style, as setup or as payoff. Besides the rules and `minimums`, a style can give `kin` (other styles that use the same resource, nearest first: where a request the pool cannot support falls back), `setupNeedsPayoff` (its setup does nothing without its own payoffs, so other themes do not take it as setup), and `lacks` (for every floor its minimums use, a short phrase a player reads when the pool misses it), and `payoffSupplies` (a payoff that also meets a setup job, such as a lord that is itself of the type, counts toward the setup that covers the other payoffs, in setup units). The top-level `tribes` holds one style for every creature type, written once: the same keys as a style (no `kin`), with placeholders each type fills in, `{type}` (the type as printed, "Elf", "Time Lord"), `{plural}`, `{types}` (either form, in a regular expression), and `{slug}` (its Tagger form, as in `typal-{slug}`). The core reads it as the style `tribal:<Type>` for any type the card needs vocabulary names (`themeStyleOf`), and only where a commander's text names the type (`namedTribes`). Its setup is creatures of the type (changelings count, as do a creature whose own text makes it every creature type and cards that make creature tokens with changeling) and cards that make creature tokens of it; its payoffs are cards the type's tag marks whose text names it (lords at 2, other rewards at 1); floors at 100 only, 20 setup and 10 payoff cards. Why each theme has its jobs and floors: `docs/builder.md`, "Theme rules". Any edit bumps the rules `version` and must be followed by `npm run theme:bulk`: `theme-bulk.json` records the rules version it was computed with, and validation fails while the two differ.

A rule's `sizes` limits it to those deck sizes. No payoff that counts a resource or waits for a threshold counts at 20 cards (Artifacts and Enchantments count payoffs, Lifegain thresholds and life-total clauses, Graveyard count and full-graveyard payoffs): a packet shuffled into 40 cards rarely holds three artifacts or a full graveyard. Spellslinger's setup floor at 20 is 4, so a packet's own instants and sorceries feed its 3 payoffs.

The 20-card template's `halfCast` (`{ "turn": 10, "minChance": 0.3 }`) keeps out of a packet the spells it cannot cast once shuffled with another packet (`halfCastable` in `packages/core/src/candidates.ts`): played as half of a 40-card deck with 16 lands, its own 8 lands, split evenly among its colors, the only sources of its colors, a spell is a candidate only with at least `minChance` to have seen its mana value in lands and, for each set of the packet's colors that can pay some of its pips, those pips in that set's share of its own lands (a hybrid pip from either color, a {2/W} pip from generic mana; a share that is not a whole number of lands is read between the two), by `turn` on the play. A split, adventure, or modal card is read by its cheapest face, a prototype card by the cheaper of its two costs. At these numbers, in a one-color packet, every spell of mana value 7 or less stays (a seven-drop with one or two pips has 0.47) but five pips of one color, or four on a seven-drop, and every spell of mana value 8 or more goes (0.23 or less); a packet of more colors has fewer sources of each and keeps fewer heavy-pip cards. The 510 official Jumpstart packets in the reference corpus play a card of mana value 7 in 77 packets and one of 8 or more in 16 (0.26% of their spells), half of those cards making themselves cheaper (Ghalta, Primal Hunger; Volcanic Salvo; Gorex, the Tombshell). The scan and both builders read the same candidates, so no 20-card request sees those cards; other templates have no rule.

`theme-bulk.json` is written by `npm run theme:bulk` from the data pack and the rules, never by hand: every common and uncommon (Un-sets left out, nonlands plus modal double-faced land cards), read at 60 cards. `styles` holds each themed style's mean tally per color class; `tribes` holds the same for the tribe of every creature type a commander in the pack names (`namedTribes`), by type, each class as the five tally numbers in `setupUnits`, `setupWeight`, `repeatable`, `payoffUnits`, `payoffWeight` order and a class with none left out, so the plan picker reads a tribe's richness as it reads a theme's. It records the data pack it was read from; rerun it after a new pack. Its version is a hash of the content and joins the config version.

`learned/` is written by `npm run learn:build`, never by hand; its versions are hashes of the content and join the config version. The judgment about how the builder uses it (weights per size, combo results and brackets) stays in `builder-weights.json` under `learned` and `combos`. Only the classic builder's secondary styles read it: nothing best fit compares at any size reads `plans.json`, `tags.json`, or the card-level `data/learned.json`, including a commander's tribes and a thin pool's plain shape that falls back to the classic builder.

What the apps show of a theme comes from the rules for every deck the grow builder made: the scan's viable styles and pool counts, the commander list's leads (a payoff job the pool pays for) and supports, the Roles bars (each floor of the alternative the deck was built to, the commander counted once), the "Setup:" and "Payoff:" reasons, Replace's jobs, the key synergies, and the card detail's style tags. A classic deck keeps the `archetypes.json` matchers its builder counted. `display-tags.json` `styles` count a card through its theme rule job (at the deck's size in a deck view, else 60).

Edit, then run `npm run config:check`: it validates shapes and cross-references, confirms every tag slug exists in the current data pack, and prints per-color match counts for each role, archetype, and display tag. `npm test` runs the shape and cross-reference validation too, but not the tag check, which needs the data pack.

Builder tiebreaks in `builder-weights.json` apply in list order after one fixed leading check: a card that fills a curve bucket still below its target beats one that does not. Card id breaks any remaining tie.

The `grow` block in `builder-weights.json` holds the constants of the grow builder (`packages/core/src/grow.ts`), which builds every deck at every size but secondary styles, a commander's tribes included: best fit, a style the player asks for by name, and each Build page option and Analyze deck. The reasoning behind each is in `docs/builder.md`.

The `picker` block holds the plan picker's constants (`pickScore` in `grow.ts`). One score ranks the finished deck of every plan, whatever built it: best fit is the first, the Build page's options and the Analyze pane's decks rank by the same number. The score is the deck's quality (each spell against the pool's cards of the same mana value and kind, creature or not, rank for rank, so a deck that plays the best cards of each slot scores 1 however many it needs), times its fit (the share of the shape's role minimums, the curve slots within tolerance, and the creature count the curve fill aims for; role targets stay out, since the fill builds to the minimums and small targets are easier to reach), times the share of spell copies the deck supports (card needs), times the share of its spells the mana casts on curve (1 in one color; quality is measured within one color set's own pool, so this keeps more colors from ranking up on equal cards). A theme also multiplies in its pool margin (`grow.marginFull`), its richness over plain bulk (`grow.richnessCap`, each side in the measure its floor counts; a tribe against its type's baseline), its depth, and the commander's lead (`grow.commanderPlan`), and is divided by `themeMargin`. A tribe the commander names is a theme like the others. Among plain shapes quality is near 1 by design (each shape plays the best cards of its slots), so fit and the mana decide, and plans within `scoreStep` tie: Midrange, then Aggro, then Control, then the themes by id.

`land-rules.json` scores nonbasic lands for the mana base (`packages/core/src/lands.ts`; the reasoning is in `docs/guides/mana-base.md`). Multi-color decks use `nonbasic` with the `colors` block. A one-color deck scores a nonbasic against the basic it replaces, so the basic scores 0 and a land gets in only above `mono.minScore`: making the deck color, or any color, gains nothing; the costs are `nonbasic.entersTapped` (scaled by the chance the land enters tapped; 0, so a tapped land is judged on what it does, and a tapped dual stays out because its second color gains nothing), and the `mono` costs below; `nonbasic.utility` counts, whatever the costs, on a land whose color identity fits the deck when the card needs reader finds its ability earned in the deck, its needs met by the deck's spells (`landUtilityEarned`). For a land of the deck color `nonbasic.utility` also counts what the land does as it enters and what a mana ability does beyond its mana (Arena of Glory's haste); `mono.planUtility` counts only a lasting ability, and a colorless land gains only on it. Fetching a land, landcycling, a rainbow or storage land's own mana (its counters, energy, chosen color, a Gate's second color, making every land a basic type), a Planet's Station line (its station abilities count on their own), keeping the land safe (Indestructible), returning it to hand or giving it to an opponent, a painland's damage, and no maximum hand size are no ability (`NO_USE` in `card-needs.ts`). Multi-color decks still read the tag alone. Lands whose mana depends on a draft (Paliano, the High City) never enter a mana base.

The data pack marks a land `entersTapped` whenever its text says it enters tapped, conditions and all. The card needs reader reads the condition (`landEntryReading` in `card-needs.ts`): the resources it names as refs, and land counts, low life, and "pay 2 life" as game state. `landEntry` holds it against the deck: a basic land type against the basics of its colors, a tribe, a Jace, or a legendary creature against the deck's spells (the deck's styles' tribe counts too), "two or more opponents" as untapped in Commander only, "pay 2 life" as a life cost instead. A condition the reader does not read stays always tapped. "Activate only if ..." mana is read the same way. The same chance counts toward the multi-color tapped cap (`colors.tappedMaxShare`) and scales `colors.entersTappedMulticolor`.

`card-needs.json` drives the card needs reader (`packages/core/src/card-needs.ts`; how the builder uses it: `docs/builder.md`). The reader splits a card's text into abilities (faces, Saga chapters, Class levels, modal bullets, keyword lines; reminder text removed; the card's names and "this creature" read as `~`) and each ability into its cost, trigger, conditions, and sentences. For every resource an ability refers to, it records where the resource appears (condition, trigger, cost, selection, count, replacement, additional cost) and its kind: a need (the ability does nothing without it), a bonus ("instead", "costs less", "or pay", "as long as ... gets +N/+N" on a body, "also", a count above a base), a drawback (an "unless" or "if you don't" over an effect that harms its owner), or nothing (unconditional; the body and keyword abilities always are). Resource ids follow `family:value`: `tribe:Elf`, `type:artifact`, `subtype:Food`, `land:Forest`, `counters:+1/+1`, `graveyard:creature`, `cast:noncreature`, `color:R`, `devotion:B`, `keyword:flying`, and the plain `lifegain`, `lifeloss`, `tokens`, `death`, `sacrifice`, `discard`, `spells`, `creatures`, `power`, `commander`, `energy`, `experience`, `format:multiplayer`. The parsing logic stays in code; the words and templates live here. Its `version` joins the config version as `n`. An object phrase that lists kinds is one set of alternatives, any of which meets it: "a Kraken, Leviathan, Octopus, or Serpent", and bare kinds joined by "and" ("Cleric, Rogue, Warrior, and Wizard spells", "Artifact, instant, and sorcery spells").

Template fields: `re`; `res` (fixed resources, any one meets the ref); `obj` (how the `{obj}` capture is read: `yours`, `graveyard`, `cast`, `card` for a card in a library or hand, `token` for what a token is); `ubiquitous` (what an object every deck has stands for: "a creature you control dies" reads as `death`, while "an Elf you control dies" reads as the Elf; the template's owner words, such as "you control", belong inside the match); `also` (resources the ref needs as well as the object: "you discard a Spirit card" needs the discard and the Spirit); `supplies` or `supply` (the phrase makes the resource rather than needing it, which is how a card supplies its own need); `counter` (read a counter kind); `place` and `kind` (overrides); `negated` ("you control no Islands"); `event` (a condition that is the event itself, so "instead" does not make it a bonus); `optional` (an action a following "If you do" depends on); `typed` (match only when the object names a resource); `notSelf` (the card itself cannot be the object: a spell it reduces, a card it searches for, a copy); `case` (case-sensitive, for a capitalized type word); `counterSupplies` (the `{counter}` is what the phrase puts, while `{obj}` is what it needs); `join` (the resources join the sentence's previous ref as alternatives: "for each Assassin you control and each Assassin card in your graveyard"); `catchAll` (a broad reading of game state, taken only when the words name no resource, and noted as game state); `ignore` (read, names nothing); `note` (a comment). Placeholders: `{obj}`, `{tok}`, `{n}` (a captured count), `{num}`, `{counter}`, `{color}`, `{mana}`; `~` is the card itself.

A deck meets a need when the card supplies it itself, or when the deck's other cards supply one of its resources to the threshold: creatures of a type for a tribe (changelings count), the deck's creatures for `graveyard:creature` (cards reach the graveyard by being played), the deck's colors for `color:` and basic land types. A card supplies its own need through another of its abilities only when that ability's own needs are met (Cleric of Life's Bond gains life only when another Cleric enters). A clause in an unparsed ability needs what its words name, at `unparsedScale` times the threshold; one that names nothing adds no need and is only reported. `npm run needs:report` reads the whole pack and writes the coverage summary (abilities parsed cleanly, and those read without the game-state fallback) to `eval/needs-coverage.md` and the unparsed work list, by shape and rarity, to `data/review/needs/unparsed.md`.
